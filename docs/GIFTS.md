# Получение Telegram-подарков с нуля

Источник данных и анимаций: [api.changes.tg](https://api.changes.tg/), проект GiftChanges.
Клиент находится в `engine/gifts_api.py`. У нового автора нет предзагруженной базы:
нужные файлы скачиваются при первом запросе в `.cache/gifts/`.
После загрузки рендер использует локальные файлы.

```python
import gifts_api as G
info = G.gift('Gift Name')
models = G.models('Gift Name', sorted_=True)
animation = G.model_file('Gift Name', 'Model Name', 'json')
preview = G.model_png('Gift Name', 'Model Name', size=512)
backdrops = G.backdrops('Gift Name')
patterns = G.symbols('Gift Name')
```

Модель означает вариант внешнего вида подарка; JSON/TGS содержит Lottie-анимацию.
Используйте фактические имена из ответа API. Модели с одинаковым отображаемым
именем различайте по имени записи API и при наличии идентификатору документа.
API даёт информацию об атрибутах; рыночные цены и курс проверяются отдельно.
Не делайте вывод о цене из процента редкости.

Перед постановкой получите `lottie.info(path)` и контактный лист полного цикла.
В рендере: `lottie.frame(path, time_seconds, size=512, loop=True)`.
Период = число кадров / фактический FPS. Пинг-понг не применяется.
Если rlottie или файл не работают, модуль может вернуть соседний PNG или прозрачный
кадр. Это аварийная подмена: проверьте непустую альфу и изменение кадров,
сообщите о сбое и исправьте его до сдачи.

Чтобы обновить данные, сохраните прежнюю выборку отдельно и запросите свежую
после удаления конкретного локального кэша с разрешения владельца.
В сценарии храните дату и URL источника. Доступность API в будущем не гарантируется.
